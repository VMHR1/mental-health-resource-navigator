# Submit-to-Publish Operational Runbook

**Last updated:** 2026-05-23  
**Production intake:** Formspree (not Cloudflare Function)

## Overview

Program listings enter the directory through a **human-in-the-loop** pipeline. Submissions are never auto-published.

```
User (submit.html)
    → Formspree inbox
    → Moderator review
    → Edit public/data/programs.json
    → npm run validate-data && npm run validate-filters
    → npm run build
    → Deploy to Cloudflare Pages
    → Smoke verify slug + sitemap
```

## Moderator review checklist

For each Formspree submission:

1. **Spam / abuse** — reject if obvious spam or rate-limit evasion
2. **PHI warning** — if patient-specific health details included, delete from Formspree and do not publish; reply asking for program-level info only
3. **Required fields** — org name, program name, care level, ages, contact, service area
4. **Neutrality** — no paid placement language; no exclusive claims without sources
5. **Verification sources** — at least one verifiable source URL or documented phone confirmation
6. **Duplicates** — match against existing `program_id`; update vs. create new
7. **Crisis programs** — confirm crisis flag and 988 routing copy if applicable

## Data edit procedure

1. Pull latest `main` / `updated-main`
2. Open [public/data/programs.json](../../public/data/programs.json)
3. Add or update program record following schema enforced by [src/js/data-validator.js](../../src/js/data-validator.js)
4. Set / refresh verification fields (`verification_date`, `verification_source`, etc.)
5. Update `metadata.generated_at` and notes when batch-updating
6. Run validation (see below)
7. Commit with message: `data: add/update {program_id} — {short reason}`

### New program ID convention

- Lowercase, underscores: `org_name_location` or existing repo pattern
- Must pass slug generation: `/programs/{program_id}.html`

## Validation commands (required before deploy)

```bash
npm run validate-data      # Schema, required fields, 90-day verification rules
npm run validate-filters   # Search/filter behavior regression tests
npm run build              # Generates dist/ + sitemap-programs.xml + slug pages
```

Full pre-launch gate (CI parity):

```bash
npm run verify             # build + validate-data + validate-filters + e2e + lighthouse
```

Optional data maintenance:

```bash
npm run verify-all-programs     # Reverification sweep
npm run audit-program-data      # Data quality audit
```

## Build & deploy

1. `npm run build`
2. Confirm outputs:
   - `dist/programs/*.html` — one file per program
   - `dist/sitemap-programs.xml` — generated by [scripts/generate-program-pages.js](../../scripts/generate-program-pages.js)
   - `dist/programs.json` — synced from public data
3. Deploy `dist/` to Cloudflare Pages (production branch)
4. Post-deploy smoke:

```bash
npm run smoke:prod
```

Manual checks:

- [ ] Random `/programs/{id}.html` loads correct program
- [ ] `/sitemap.xml` and `/sitemap-programs.xml` return 200
- [ ] New/edited program appears in homepage search

## Rollback

If a bad deploy or bad data commit reaches production:

1. **Revert git commit** on production branch and redeploy, OR redeploy previous Cloudflare Pages deployment from dashboard
2. **Invalidate cache** if stale `programs.json` served (check `_headers` cache rules)
3. **Notify** if incorrect clinical/crisis contact info was live — priority rollback
4. Document incident in deploy log

```bash
git revert <commit-sha>
npm run verify
# push and deploy
```

## Secrets & security

- **Do not** commit Formspree secrets beyond public form endpoint URL
- **Do not** auto-merge Formspree payloads into `programs.json`
- **Do not** include moderator credentials in repo
- Formspree inbox access limited to moderators
